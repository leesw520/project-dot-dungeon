# 거점 고정 배경 + 독립 건물 PNG 패키지 v0.3

## 핵심 동작

이전 시안의 가장 큰 문제인 **건설 전/건설 후 배경이 서로 달라지는 문제**를 해결했습니다.
빈 거점 지도 하나(`background/hub_empty_1672x941.png`)를 고정하고, `buildings/master/*.png`의 RGBA 건물 이미지만 지정 좌표로 합성합니다.

- 빈 지도: `background/hub_empty_1672x941.png`
- 실제 건설 가능 위치 설명: `previews/hub_slots_annotated_960x540.png`
- 건설 완료 예시: `previews/hub_developed_1672x941.png`
- 초기 거점 예시: `previews/hub_initial_1672x941.png`
- 모든 좌표: `maps/hub_placements.json` (고해상도 및 480×270 각각)
- 단순 표: `maps/building_positions.csv`
- 재현 코드: `scripts/render_from_json.py`

## 포함 데이터

- 건물 PNG **13개**: 던전 게이트(배경에 고정), 작업대, 창고, 대장간, 작전 천막, 연금술 공방, 교역소, 모험가 길드, 기록보관소, 약초밭, 전송장치, 취사장, 낚시터
- 오브젝트 PNG 41개 (보조 소품)
- 건설 상태 마커 PNG 3개
- 고정 배경 1672×941 원본 및 480×270 표시용
- 건물마다 소형 56×40 별도 PNG (가독성은 별도 확인 필요)

## 배치 데이터 안내

`placements`에서 건물 ID별 `file`, `x`, `y`, `width`, `height`를 읽어 그리면 됩니다.
모두 배경의 왼쪽 위를 (0,0)으로 하는 원본 1672×941 좌표입니다. 이미지는 픽셀 그대로 합성하는 게 아니라 `width`×`height`로 리사이즈 후 합성합니다.
게임 480×270에는 `game_x`, `game_y`, `game_width`, `game_height` 필드가 있으므로 사용하거나 화면 전체의 스케일 비율을 적용합니다.

건물이 없는 구획은 `markers/build_available.png`를 별도로 렌더링해서 건설 예정 상태로 나타낼 수 있습니다. 원본 배경에는 건설 표시를 넣지 않았습니다.

## 예제 실행

`pip install pillow` 후 패키지 루트에서:

`python scripts/render_from_json.py --scenario developed`

## 중요한 제약과 솔직한 설명

1. 원본 고정 배경 그림에는 **일반 부지 9개 + 중앙 광장 1개 + 강변 1개 = 총 11개**가 있습니다. 이전 기획서의 논리적 7×5(35칸) 건설 부지 전부가 이 그림에 표현된 것은 아닙니다. 전체 35칸을 동시에 표시하려면 맵을 다시 디자인해야 합니다.
2. 배경에 던전 입구가 이미 그려져 있으므로 `dungeon_gate.png`를 같은 위치에 또 렌더링하면 중복됩니다. 현재 고정 오브젝트로 취급합니다.
3. 중앙 광장(S10)은 **전송장치 또는 취사장 중 하나를 선택**하는 임시 대체 슬롯입니다. 13개 건물을 한 번에 모두 놓는 그림은 아직 아닙니다.
4. 낚시터 이미지는 푸른 물 부분을 일부 제거한 `fishing_dock_river_overlay.png`를 사용해 강 배경이 변하지 않도록 했습니다.
5. 두 AI 생성 소스의 작화가 픽셀 단위로 100% 정확히 일치하지는 않지만, 빈 지도와 건설 후 지도는 **기술적으로 동일한 배경 픽셀을 공유합니다.**
6. 작화 원본은 1672×941입니다. 480×270으로 한번에 축소하면 세부 묘사가 줄어들 수 있으므로 최종 게임 화면의 도트 가독성은 개발측에서 검수해야 합니다.
